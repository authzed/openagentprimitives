# BrowserToolbox

**Group** `agentprimitives.authzed.com` · **Scope** Namespaced · **Short names** `btb`

BrowserToolbox declares a per-session browser the agent can drive: which
sites it may reach and whether the LLM may act on the page or only read it.

Namespaced. An AgentClass references it via AgentClassBrowserToolboxRef,
and the AgentSession reconciler snapshots the referenced spec into
status.resolvedBrowserToolboxes at session start (see
ResolvedBrowserToolbox), frozen for the session's lifetime exactly like a
SidecarToolbox.

Phase A deliberately ships a narrow field subset: Access covers only an
explicit allowlist/blocklist of sites (Task 1's pkg/tools/browserpolicy
decides admission from it), Interaction is act/readonly, and State is
pinned to "ephemeral" -- there is no persistent browser profile/identity
yet. Those arrive in later phases (identity-sourced sites in Phase B,
persistent state in Phase C) as additive fields, not a breaking change to
this spec.

## Spec

| Field | Type | Description |
| --- | --- | --- |
| `spec.access` \* | `object` | Access is the site allowlist/blocklist the browser's egress is evaluated against. |
| `spec.access.identity` | `string` | Identity is the name of an AgentIdentity (in this BrowserToolbox's namespace) carrying a directCredentials credential this browser binds to -- a Phase B addition. Allowlist-only: the two XValidation rules on BrowserToolbox.Spec refuse it under Mode=blocklist, because a general-access browser has no legitimate use for a credential reference. Identity name syntax and existence are not checked here -- that is the Task 7 BrowserToolbox reconciler's job (Valid=False when the reference is missing or has no directCredentials credential). |
| `spec.access.identitySites` | `boolean` | IdentitySites, when true, folds every host Identity's directCredentials catalog lists into this allowlist, alongside any explicit Sites -- a Phase B addition. Requires Identity to be set (enforced by the second XValidation rule on BrowserToolbox.Spec). This field only records the bit; deriving the actual host names from the identity's source happens in the AgentSession reconciler (DeriveBrowserEffectiveSites, Task 7) and is recorded onto status, not here. _(default: false)_ |
| `spec.access.mode` \* | `string` | Mode is "allowlist" (only Sites are reachable) or "blocklist" (every site except Sites is reachable). _(enum: allowlist \| blocklist)_ |
| `spec.access.sites` | `[]object` | Sites is the set of hosts Mode interprets. Matching is suffix-by-label unless Exact is set: a Site with Host "example.com" also matches "www.example.com" and "a.b.example.com", but never a lookalike like "notexample.com" -- pkg/tools/browserpolicy.Match does label-boundary comparison, not a raw string suffix check. Exact pins the entry to the literal host only. |
| `spec.access.sites[].exact` | `boolean` | Exact pins this entry to the literal Host only, disabling the default suffix-by-label subdomain match. |
| `spec.access.sites[].host` \* | `string` | Host is the DNS hostname this entry covers, matched suffix-by-label (see BrowserAccess.Sites) unless Exact is set. |
| `spec.access.sites[].unattended` | `boolean` | Unattended marks this site's web_host#act grant as operator-approved: the AgentSession reconciler's runner writes the slot_grant_act relationship for this host at session cold start, unconditionally, with no human plan-gate card -- the operator's declaration of Unattended IS the authorization, exactly as an approved card would be. A Phase C addition; the third field-scoped XValidation rule on BrowserToolbox.Spec requires access.mode=allowlist and access.identity whenever any site sets this, so an unattended grant is always for a specific, bound-identity session and never for a general-access (blocklist) browser. The default marker below lands a structural default on every site, even one that omits the field entirely -- without it, the third XValidation rule's `s.unattended` on a plain site with no explicit value errors evaluation ("no such key: unattended") instead of reading false, and CEL's fail-closed-on-error semantics then refuse EVERY BrowserToolbox create, not just an unattended one. _(default: false)_ |
| `spec.interaction` | `string` | Interaction gates whether the LLM may act on the page (click, type, navigate) or only read its rendered content. act -- full interaction. readonly -- observation only; no mutating actions are dispatched. _(enum: act \| readonly; default: act)_ |
| `spec.state` | `string` | State selects how the browser's session state (cookies, storage) is retained across turns: "persistent" captures cookies + localStorage for the effective sites into a per-session Secret and re-injects them across reap and wake (spec §1.4); "ephemeral" keeps a clean profile every pod boot and captures nothing. An explicit "persistent" requires access.identity (the field-scoped XValidation rule on BrowserToolbox.Spec). DELIBERATELY NOT DEFAULTED at admission. An unset value is resolved in code at the AgentSession snapshot (controller.go) to "persistent" when an identity is bound and "ephemeral" otherwise -- a static kubebuilder default would mask that identity-driven default, so the field is left omitempty and enum-but-not-defaulted so an unset field stays distinguishably empty. _(enum: ephemeral \| persistent)_ |

<small>\* required</small>

## Status

| Field | Type | Description |

| `status.conditions` | `[]object` | Conditions carries this BrowserToolbox's Valid condition. |

| `status.observedGeneration` | `integer (int64)` | ObservedGeneration is the spec generation this status reflects. |
