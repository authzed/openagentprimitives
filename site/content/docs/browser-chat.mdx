# Browser web chat

<p className="doc-lede">
  The web daemon serves a chat at <code>/sessions</code> — a browser surface for talking to any installed
  agent, with no Slack app and no terminal. It's what the <a href="#/install-desktop">Desktop</a> menubar's
  "New chat…" opens, and it renders the same threads, approvals, and status as every other channel.
</p>

## Starting a session

Sign in, pick an agent, and say what you need. The session opens in its own view and streams the reply as it
comes.

## One owner per session

Each browser session is owned by the person who **started** it, and every request to read or drive it is
authorized per-session against the same graph as everything else — signed in over the trusted origin, checked
on `agentsession#interact` before the message and again before the live stream. So the browser surface is a
direct line between you and an agent, not a console anyone can pick up.

The *multiplayer* story — many people in one conversation, each authorized independently, approving each
other's steps — is [Slack](#/slack)'s, where the identities and the thread are real. Reach for the browser chat
to drive an agent yourself; reach for Slack when a team shares the thread.

<Callout kind="tip" title="Reached over loopback">
  On Desktop the chat is served over a loopback-only connection — nothing is exposed to the network. On a
  cluster it's behind the same sign-in and authorization as the admin console.
</Callout>
