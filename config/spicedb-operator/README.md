# `config/spicedb-operator/` — vendored upstream operator

SpiceDB is not deployed directly. `oap install` creates a `SpiceDBCluster` CR and
lets authzed's spicedb-operator reconcile the actual Deployment, Service, and
config. This directory vendors that operator so the whole thing installs from
the embedded bundle with no network fetch.

## Files

- `bundle.yaml` — the upstream **authzed spicedb-operator v1.27.0** release
  bundle, copied verbatim. It carries its own `spicedb-operator` Namespace, the
  `spicedbclusters.authzed.com` CRD, ServiceAccount, ClusterRoles/Binding, the
  `update-graph` ConfigMap, and the Deployment. Do not hand-edit it — replace it
  wholesale when bumping the version, and update the pinned image in
  `pkg/platform/apimage`.

`kustomization.yaml` deliberately sets **no `namespace:`**. The bundle installs
into its own namespace and defines cluster-scoped objects; rewriting it into
`agentprimitives-system` would break the bundle's own namespace and RBAC wiring.

Not generated by `mage gen:api`, but not hand-authored either — treat it as a
vendored artifact.
